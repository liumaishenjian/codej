# ADR-113：可靠交付与有界事件诊断

Proposed；2026-09-12；S15，CLI-03/04/09 L2、PLAN-01 L1不变。

参考AUTH-SRC-2026-07-29-A（Observed）：REPL→handlePromptSubmit→messageQueueManager把提交、队列、活动请求与展示状态分开；队列操作有独立记录。结合ADR085/112的宿主握手机制，本项目继续由Java调度，仅在TUI保留关联与取消意图，不增加自动排队或重发功能。

本项目独立选择：诊断不复制参考记录正文的方式。内存最多64条，仅白名单事件种类、白名单结果码、界面阶段与路由判定；重复事件聚合计数，不保存Session/Run/Request原始ID、正文、参数、路径或异常信息。Ctrl+O详情查看，普通聊天不输出内部流水；退出即清除，无新文件、命令、日志服务或遥测。诊断覆盖是否因序号、会话、请求、Run或连接状态过滤，但不宣称能复原未收到的底层协议字节。

交付契约：非取消终态的finalText始终可见，验收失败提示另行保留，不能为强调失败而吞正文。普通成功终态既无finalText也无本Run正文时明确说明没有可显示结果；计划模式无审核面板时仍提示未生成可审核计划，即使有解释文字。用户取消继续禁止迟到正文；旧Run/请求不能重新激活面板。诊断与正文缓存分离，避免旧缓存掩盖最新事件。

展示约束：仅在有异常提示且无待决面板的Ctrl+O详情末尾显示最近12项，正常聊天和审批不出现诊断流水；内存容量仍为64项。宿主run.cancelled终态把未结束工具标为取消；仅transport failure时则明确结果未知，不宣称副作用已撤销。

验证：连续运行、排队、工具失败纠正、审核/结果、空结果、计划缺审核、验收失败带说明、取消迟到、断连及下一轮；隐私白名单与容量/重复聚合；六尺寸及Java Fake跨进程组合回归。持久恢复、原始协议抓包、自动重放、参考实机视觉与跨平台仍非本批范围。
