## G1：范围与可证伪目标

- 目标是状态/持久化/权限独立于 Plan 审批工件的 Session-local Task Board；Plan planning 与批准 execution 复用同一 Board 和 Task identity，批准边界不能从 Markdown 派生第二套 Task，也不能反向审批 Plan 或替代 Evidence。
- L2 验收覆盖三态与派生 blocked/recovery、依赖 DAG、CAS/claim epoch、四个统一 Pipeline Tool、Resume/Fork、root/child scope、stable snapshot、stdio `/tasks` 与 Ink 面板。
- 关键反证包括：并发 claim 只能一次成功、旧 epoch/越权/环依赖必须拒绝、terminated Run 不自动重放、日志随 mutation 近线性增长、Plugin/MCP spoof 不能获得 Session state 权限。
- Team Board、跨进程订阅、peer messaging、lease 与自动领取延期 `SUB-11`。

结论：Accepted。

## G2：研究与 ADR

- ADR-088 冻结 root-owned Board、单向 canonical `blockedBy`、派生 `blocks/blocked/recoveryRequired`、revision/tombstone、claim 与幂等契约。
- 四个 Tool 采用独立 snake_case schema，只能经过唯一 `ToolExecutionPipeline`；Permission 仅放行精确 BUILT_IN name/effect 组合。
- Session JSONL 保存增量 mutation delta；Resume 重建，Fork 写单次完整 seed；稳定协议只读，不开放 mutation 旁路。
- Ink 只消费事件和快照，不取得 Task 执行权，也不修改 canonical final。

结论：Accepted。

## G3：独立实现

- Domain/Core 不依赖 Spring、文件系统、JSON、stdio 或 Ink；Session journal、stable/stdin 和 TUI 均位于架构边缘。
- `task_create/task_update/task_list/task_get` 已注册为生产 BUILT_IN Tool，并复用 Permission、Approval、Lifecycle、Hook、截断与结构化错误主链。
- root 可向 `delegate_agent.taskIds` 提出候选 ID，宿主重新验证并注入最多 32 项的 child capability；嵌套 child 不继承 parent Board。
- 新增核心协议、安全边界、状态机和公共契约均使用中文 Javadoc；JSON null 通过 `JsonNull` 保持字段缺失与显式删除的差异。

结论：Accepted。

### 第三、四次 corrective（窄 Adapter 已由第六次纠正撤销）：真实 XLSX、窄状态协议与 Run deadline

- 批准 Plan 的 `task_update` 只公开 `task_id/status/active_form`，Java 注入 Plan identity、CAS revision、

- Ink 进行中主行使用实心符号/bold，下一行显示 dim activity 与有界省略号；完成主行真实
  strikethrough/dim 且移除 activity。React renderer 直接断言节点属性，不以纯文本替代样式证据；
- 旧“把交互总 Run timeout 从 5m 提升为 30m”修复被后续真实 Provider 流程再次证伪；当前 30m 只属于 Print/显式调用方 hard deadline，Interactive/Plan/approved-plan 的 total model/tool/deadline 均 absent；

### 第五、六次 corrective：移除隐式总预算并统一 Plan Task identity

真实 Provider 日志先证明 `{task_id,status:COMPLETED,active_form}` 会被旧 parser 拒绝，随后又证明规划期
中文 task-1..N 与批准后 Markdown seed 是两套 identity/capability，产生 `TASK_CAPABILITY_DENIED`、
`TASK_NOT_FOUND` 和 UI 长期 0/N。授权源码复核确认：

- `--max-turns` 只对显式 Print 生效；普通 Interactive/Plan 不存在默认总回合限制；
- Plan Mode 使用普通 TaskCreate/TaskUpdate/TaskList/TaskGet，批准工件不重建 Task Board；
- 模型 TaskUpdate 只提交 taskId 和可选业务字段，宿主读取当前任务并处理内部并发控制。

当前实现删除 `AgentBudgetPolicy` 的 adaptive/absolute ceiling、`ApprovedPlanTaskSeeder`、
`ApprovedPlanTaskUpdateTool` 和 Task final-only gate。Interactive/Plan/approved-plan 的总 model turns、
Tool calls、Run deadline 均 absent；Print/API/SDK 显式 hard limit 保留。Plan 两阶段共享同一
Session Board 与四个 Tool；通用 `task_update` 公开 subject/description/active_form/status/owner/dependency，
内部继续使用 capability、强 CAS、claim 和稳定 phase call ID。

确定性真实 Java→stdio→Ink E2E 在规划期创建五个中文 Task 和依赖，通过真实 Ink 审批选择器建立
execution Run correlation；批准执行先 list/get 并验证同一 task-1..5，再逐项 IN_PROGRESS/COMPLETED。
活动 Run 的最多两行投影固定在 Model 状态之后、Tool 历史之前，慢命令期间仍显示 `active_form`；最终
`/tasks` 显示五个勾选项，组件策略直接断言 `strikethrough=true/dimColor=true`。同一隔离 Workspace 从文件不存在开始生成真实 OpenXML XLSX，
并由第二 JVM 重开验证 18×7=126 行。最终命令与统计在本次提交前更新，不复用已撤销窄 Adapter 的历史通过数字。
